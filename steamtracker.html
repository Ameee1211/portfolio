Steam
Tracker

Steam will tell you that you have played a game for three hundred hours. It will not tell you how long you played today. This app keeps every session you add, so the hours are in front of you instead of buried in a lifetime total.

01 — The interface

Two screens: the page you land on, and the list it fills.

The homepage is a Steam store image, one sentence about privacy, and the form straight underneath. There is no sign-up to get past and nothing to click through. The history lives below it on the same page, newest first, with a date and a running total on every entry.

02 — How it behaves

Two steps, and a gate between them.

Check reads the three fields and writes them into a mint card. Add puts that card into the history. Between the two clicks there is a preview you can read, and before the first one there are six ways to be told what is missing — each message sitting directly under the field that caused it.

Step 01

Fill in three fields

Name, hours to one decimal place, and one of eleven genres. Clear empties all three at once, which was the tutor's suggestion.

Step 02

Read it back on the card

Check writes the entry into a mint card: name, genre, this session, the running total for that game, and the date. Nothing is saved yet.

04 — Mockup to mockup

The first version was bright, full width, and had no way to clear the form.

My tutor's feedback on version one was blunt: you cannot read the game information against that background. So I went and looked at sites that are easy to read, and wrote down what they had in common — a white page with a single accent colour, content held inside margins instead of stretched across a wide screen, and instructions placed where the user is about to act.

Version one also depended on cover art fetched from Steam. When I could not find a public endpoint for it, the pictures came out of the design and the three fields stayed — which is why version two has no thumbnails in the history at all.

Mint greenChosen as the single accent because it sits next to Steam without copying it.
MarginsContent pulled into the middle so a wide screen still reads left to right.
ClearOne button to empty all three fields — the tutor's suggestion.
DividersFour sections made visible, so the page reads in steps rather than as one column.

05 — Phone, tablet, desktop

Three blocks in the SCSS, but only one breakpoint that changes the layout.

Above 1024px the two steps sit side by side: you type on the left and read the result on the right without moving your eyes. At 1024px and below that stops being possible, so the grid collapses and the preview card drops underneath the form, in the order you use it.

06 — Built, and what holds it together

Week six was the server. Week eight was the bundler.

The build followed the course in order: a Node and Express server serving a static folder, then Parcel and SCSS on top of it, then the form and the history. Nine commits between 28 May and 7 June 2023, one working step in each. There is no database behind any of it — the whole app is one array in localStorage, redrawn by a single function every time something changes.

01

Nine commits, named for the change

From “add the homepage” to “finish mobile version”. Small enough that any one of them could be the version that worked.

02

SCSS for the repetitive part

Nested selectors and variables saved the responsive layer from being written out three times by hand. It is also the least tidy code in the project.

Read on loadThe list is rebuilt from localStorage every time the page opens.
Write on changeAdd and Delete rewrite the same array, then call the same redraw.
Newest firstRecords are pushed to the front, so the last session sits at the top.
Totals are not per dayThe number above each card adds up the whole array, which only equals one day while the list is one day long.

The function doing that redraw is updateGameHis(), lines 171 to 253 of a 291-line script.js. It empties the list, reads the array back out of localStorage, writes a card per record, then attaches the open and delete handlers to elements that did not exist a moment earlier — the longest function in the file, and the only one I commented line by line.

07 — Known issues & future versions

Three things left open at the end. The first still bothers me.

These were the notes I left for myself when the assignment was handed in, in the order I would tackle them. The first one is the feature I actually wanted and never shipped. It failed on the API, not on time.

01

Reading your Steam library — wanted, and not built

The whole first mockup was built around this: you type a game, the app recognises it, pulls the cover art and the hours you have already put in, and the history fills itself. I went looking for the endpoint that would allow it, and found three problems that a static website cannot get around.

  • It needs a server, and this app has none. Every Steam Web API call requires a developer key, and Steam's responses carry no CORS headers — so a browser on your machine is not allowed to call them directly. The key would have to sit in a small backend that forwards the request, which is exactly the thing this project was built to avoid.
  • Steam counts totals, not sessions. The API returns lifetime hours per game and a rolling two-week figure. There is no “this session started” event, so the real-time monitoring people picture when they hear “connect your Steam account” is not something the API can supply. You would have to keep a page open and poll it, then subtract the difference.
  • It only works if the player is already public. A Steam profile with its game details set to private returns an empty library. The first thing the feature would do is tell half its users that their account does not exist.

So it stayed manual: three fields, typed by hand. By the time I understood the constraints I also understood that a tracker you fill in yourself is the only version of this idea that runs as a plain web page — and the typing is what makes the number feel like yours.

02

The responsive SCSS is longer than it needs to be

The tablet and phone blocks repeat rules that differ only by a margin. They work, and they are the least tidy code in the project.

Next version: fold both into one mixin that takes the spacing as an argument, instead of writing the block out twice.

03

The homepage background scrolls away

The Steam artwork moves with the page instead of staying put, so the one moment that sets the mood is gone as soon as you move.

Next version: background-attachment: fixed on desktop and a static crop on mobile, where the fixed version behaves badly.
